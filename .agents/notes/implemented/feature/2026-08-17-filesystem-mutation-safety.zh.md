# Agent Note: 文件系统变更安全

Status: implemented

[English](2026-08-17-filesystem-mutation-safety.md) | 中文

## 问题

长文本文件会放大严格编辑匹配和无保护覆写的失败成本。首尾空白、逐行尾空白、行尾格式或全角标点的微小差异可能拒绝意图清晰的编辑；意外覆写则没有提供方管理的恢复副本。根据内容猜测字面反斜杠序列是否是传输转义，可能修复散文，却破坏源代码、正则表达式或 Windows 路径。

安全行为必须在本地、沙箱与 E2B 文件系统之间一致。它不能依赖 Git 仓库、修改无关仓库状态，也不能让诊断相似度静默选择变更文本。

## 决策

`@deepseek-ai/dsh-fs` 拥有一个由本地与 E2B 提供方共享的纯编辑匹配器。progressive 模式按顺序累计尝试 LF 规范化精确匹配、修剪搜索文本、逐行尾空白和全角 ASCII/U+3000 策略，并只采用第一个产生匹配的级别。未设置 `replaceAll` 时仍要求唯一匹配。按 Unicode code point 计算的有界 Levenshtein 候选只用于错误诊断。

变更调用携带显式 `FsWriteOptions` 或 `FsEditOptions`，其中包括 required/disabled 备份策略。提供方在目标锁内完成初始校验后、原子发布前创建保留原始字节的备份，备份完成后重新检查源版本；备份存储失败时保持目标不变。本地存储默认使用私有的目标散列目录、不可预测名称、仅所有者权限和三个版本保留策略。E2B 在远端沙箱内使用等价的私有存储。沙箱提供方会在继承的备份或变更工作前执行 fresh-target 包含关系检查。

工具字符串默认为 `text`，保留 JSON 解析后的值。`escaped` 显式请求额外一层严格解码，只接受 `\\`、`\n`、`\r` 和 `\t`。未知序列和末尾孤立反斜杠会在任何文件系统副作用前失败。`write`、`edit` 与 `str_replace_editor` 公开对应 format 字段；变更结果公开备份路径和字节数，但不公开内部源版本。

## 考虑过的替代方案

**每次变更后自动创建 Git commit 或 side ref。** 拒绝，因为文件系统提供方可能运行在仓库外，会话可能包含无关未提交工作，而隐式提交会改变用户可见的仓库历史。提供方管理的备份覆盖实际执行变更的能力，即使没有 Git 也可用。用户仍可在工作流边界显式提交。

**把近似匹配作为自动降级。** 拒绝，因为编辑距离不能证明意图。候选为模型提供可操作上下文，同时避免近似文本修改错误段落。

**启发式修复转义。** 拒绝，因为同一个字面 `\n` 可以是有效散文、源代码、正则或路径内容。显式 format 字段让传输意图可检查，并让默认文本保持无损。

**目标旁的 `.bak` 文件。** 拒绝，因为它会污染项目目录、与用户文件冲突、暴露可预测名称，并把恢复数据混入源代码管理。提供方管理的私有根目录让保留与权限只有一个所有者。

## 后果

降级匹配在不削弱唯一性的前提下提高容错，失败编辑通过稳定结构化错误码提供有界候选。修改现有文件的 write/edit 默认可恢复，创建和匹配失败不产生备份。备份保留清理发生在发布后，清理失败时可暂时超过配置数量。

备份后的源版本复查会缩小外部修改竞态，但不提供跨进程 compare-and-swap 发布。E2B 恢复能力只在远端沙箱生命周期内有效。显式 escaped 模式增加 schema 和提示词成本，但默认值精确保留代码与路径，非法转义也无法创建备份或修改目标。
